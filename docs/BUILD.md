# Building SmartLights

The dev machine is Windows (git, gh, Node 24, Docker; no Swift, no Xcode). Apple builds happen only on GitHub Actions macOS runners (or any Mac). Never claim an Apple-side build passes without a green CI run.

## Project generation: XcodeGen

Decision (T0.1): the Xcode project is **generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml`** and is **not committed** (`SmartLights.xcodeproj` is a build artifact; it is in `.gitignore`). Reasons: `project.yml` diffs are small and reviewable; agents on Windows can edit it without Xcode; no merge conflicts in `project.pbxproj`.

| Item | Value |
|---|---|
| Spec | `project.yml` (repo root) |
| Generated project | `SmartLights.xcodeproj` |
| App target / scheme | `SmartLights` |
| Unit-test target | `SmartLightsTests` (sources in `App/Tests`, Swift Testing) |
| Bundle id | `com.sinap.smartlights` (tests: `com.sinap.smartlights.tests`) |
| Deployment target | iOS 18.0, Swift 6 language mode, strict concurrency complete |
| Info.plist | `App/Resources/Info.plist` (hand-written, `GENERATE_INFOPLIST_FILE = NO`) |
| Entitlements | `App/SmartLights.entitlements` (default) / `App/SmartLights.multicast.entitlements` (after Apple grants multicast) |
| App Group | `group.com.sinap.smartlights` |
| Keychain access group | `$(AppIdentifierPrefix)com.sinap.smartlights` |
| Local packages | `Packages/LightCore` (product `LightCore`), `Packages/NetKit` (product `NetKit`) |

To add a source file to the app: just put it under `App/` (any subfolder); XcodeGen picks it up. To add a package or extension target: edit `project.yml` (see comments there).

## macOS (CI or a Mac)

```sh
brew install xcodegen
xcodegen generate                       # creates SmartLights.xcodeproj

# Simulator build + tests, no signing (what CI does)
xcodebuild test \
  -project SmartLights.xcodeproj \
  -scheme SmartLights \
  -destination 'platform=iOS Simulator,name=iPhone 17' \
  -resultBundlePath build/SmartLights.xcresult \
  CODE_SIGNING_ALLOWED=NO

# Package tests on macOS
swift test --package-path Packages/LightCore
swift test --package-path Packages/NetKit
```

Pick a simulator that exists on the runner (`xcrun simctl list devices available`).

Device / TestFlight builds need signing: pass `DEVELOPMENT_TEAM=<TEAMID>` (and the App Store Connect API key, see T0.2) to `xcodebuild archive`. The App ID `com.sinap.smartlights` needs the HomeKit and App Groups capabilities enabled and the App Group `group.com.sinap.smartlights` registered in the developer portal.

### Multicast entitlement

`com.apple.developer.networking.multicast` is a managed capability that Apple must grant. Until then all builds use `App/SmartLights.entitlements`, which does not contain it. Once granted (and enabled on the App ID), either change `CODE_SIGN_ENTITLEMENTS` in `project.yml` or pass it to the signed build only:

```sh
xcodebuild archive ... CODE_SIGN_ENTITLEMENTS=App/SmartLights.multicast.entitlements
```

Keep both entitlements files identical apart from the multicast key. The app must keep working without it (unicast sweep + manual IP fallback).

## Windows / Linux: codec tests in Docker

Codec packages (pure Swift, Foundation + swift-crypto only) build and test in the official Linux Swift image. From the repo root:

```powershell
# PowerShell
docker run --rm -v "${PWD}:/src" -w /src/Packages/LightCore swift:6.1 swift test
docker run --rm -v "${PWD}:/src" -w /src/Packages/Providers/WiZKit swift:6.1 swift test --filter WiZCodecTests
```

```sh
# bash / Git Bash (MSYS_NO_PATHCONV stops Git Bash from mangling /src)
MSYS_NO_PATHCONV=1 docker run --rm -v "$PWD":/src -w /src/Packages/LightCore swift:6.1 swift test
```

Tip: the `.build` folder created inside the container is Linux-specific; add `--scratch-path /tmp/build` (or delete `.build`) if you switch between Linux and macOS builds of the same checkout. `.build/` is gitignored.

The app target, provider (transport) products, and anything importing Network/HomeKit/SwiftUI cannot be built here; push and read CI:

```sh
gh run list --limit 5
gh run view <run-id> --log-failed
```

## Formatting

`.swift-format` at the root configures [swift-format](https://github.com/swiftlang/swift-format) (4-space indent, 120 columns). It ships with the Swift 6 toolchain:

```sh
swift format lint --recursive App Packages
swift format --in-place --recursive App Packages
```

In Docker: `docker run --rm -v "${PWD}:/src" -w /src swift:6.1 swift format lint --recursive App Packages`.

`.editorconfig` covers whitespace for all other files.

## Notes

- `ITSAppUsesNonExemptEncryption` is `false` in Info.plist (standard TLS/HMAC/AES for device protocols only). Revisit if the app ever ships proprietary encryption.
- The app icon set (`App/Resources/Assets.xcassets/AppIcon.appiconset`) has no image yet; add a 1024x1024 PNG before the first TestFlight upload.
