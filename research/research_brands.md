# Smart-light brand survey for a third-party iOS controller app (US market, Oct 2026)

Scope: every mainstream consumer smart-light brand except Hue, WiZ and AiDot/Linkind (researched separately).
Research date: 2026-10-26. GitHub star counts / last-push dates pulled live from the GitHub API on that date.
Difficulty = 1 (trivial, documented local API) to 5 (cloud-only reverse-engineering or no path at all) for a native Swift app.
Items marked **[uncertain]** could not be confirmed from a primary source; items marked **[knowledge]** come from prior familiarity with the protocol and were not re-verified this session (the shared web-search budget ran out part-way through).

## 2. Per-brand notes and gotchas

### LIFX
- LAN docs: https://lan.developer.lifx.com/docs/communicating-with-device (UDP 56700, single-packet messages, broadcast `GetService` -> `StateService`; mDNS `_lifx._udp` on fw >=4.110 is "the preferred method going forward").
- HTTP API: https://api.developer.lifx.com/reference/authentication (token from cloud.lifx.com/settings; Bearer or Basic with token as username; HTTPS only, 426 on plain HTTP) and https://api.developer.lifx.com/reference/rate-limits (120 req / 60 s per token, `X-RateLimit-*` headers). The docs call it an "OAuth 2 access token" but document only personal tokens; no third-party OAuth authorization flow is documented **[uncertain]** - plan on users pasting a personal token.
- Matter: all factory-Matter products use an ESP32-C6 and can run Wi-Fi or Thread; Thread beta announced Aug 2026 (requires re-pairing) - https://homekitnews.com/2026/08/25/lifx-opens-thread-beta-for-its-existing-matter-over-wi-fi-devices/ , https://support.lifx.com/hc/en-us/articles/43137260925079-How-does-the-LIFX-Thread-beta-work . Older units received Matter by firmware selectively. Budget "Everyday" A19s (Oct 2025) are Matter-over-Wi-Fi - https://homekitnews.com/2025/10/24/lifx-launches-budget-matter-enabled-smart-bulbs/ .
- HA `lifx`: Local Polling; works without cloud - https://www.home-assistant.io/integrations/lifx/ .
- iOS: UDP via `Network.framework` (`NWConnection`) + mDNS via `NWBrowser`. Local-network privacy prompt (`NSLocalNetworkUsageDescription`, `NSBonjourServices`) required.

### TP-Link Tapo / Kasa
- python-kasa supported list (https://raw.githubusercontent.com/python-kasa/python-kasa/master/SUPPORTED.md): "All Tapo devices require authentication"; Kasa KL/LB bulbs and KL400/420/430 strips do not (legacy firmware). Tapo bulbs listed: L430C/P, L510B/E, L530B/E/EA, L535E, L630; strips L900/L920/L930.
- HA `tplink` (Local Polling): "If your device is a newer Kasa or Tapo device it will require your TP-Link cloud username and password to authenticate for local access" and some firmware needs the Tapo app's **Tapo Lab > Third-Party Compatibility** switch - https://www.home-assistant.io/integrations/tplink/ . TP-Link's own FAQ (https://www.tapo.com/us/faq/714/) says the toggle is off by default, that third-party apps need your TP-Link account credentials, and that enabling it "can reintroduce security vulnerabilities".
- Protocol: KLAP = two-round handshake with SHA-256/SHA-1 of credentials, then AES-CBC with session key over HTTP :80 (python-kasa is the reference; `esp-tapo` and `KasaTapoClient` reimplement it - https://community.home-assistant.io/t/esp-tapo-esphome-custom-component-to-control-tapo-devices-locally-without-home-assistant/1022611 ). A newer "TPAP" protocol is appearing on some Tapo devices (KasaTapoClient notes, https://feed.nuget.org/packages/KasaTapoClient). Expect protocol churn.
- Matter: Tapo L535E is Matter-certified (https://www.tapo.com/en/product/smart-light-bulb/tapo-l535e/); Matter bulbs can be commissioned by any Matter controller, bypassing KLAP entirely.
- Libraries: python-kasa (1,772 stars, pushed 2026-10-25); `mihai-dinculescu/tapo` Rust crate (864 stars) is a good port reference for Swift because it is strongly typed.

### Govee
- LAN API (Govee WLAN guide https://app-h5.govee.com/user-manual/wlan-guide - page body did not load for me; the openHAB binding https://www.openhab.org/addons/bindings/govee/ documents the same): enable "LAN Control" in device settings (toggle "can take several minutes to appear"); multicast 239.255.255.250:4001 for `scan`, device replies to your :4002, commands (`turn`, `brightness`, `colorwc`, `devStatus`) to device :4003. No auth, plaintext JSON. ~150 SKUs listed (H6042 ... H805C); homebridge-govee notes the plain A19 bulbs are not on the LAN list (https://app.unpkg.com/homebridge-govee@10.15.0/files/lib/connection/lan.js).
- Cloud Developer API: key via app (https://developer.govee.com/reference/apply-you-govee-api-key); `GET /router/api/v1/user/devices` (https://developer.govee.com/reference/get-you-devices, 30 rpm/account) returns a capability schema per device; `POST /router/api/v1/device/control` (https://developer.govee.com/reference/control-you-devices, 120 rpm/device, 720 rpm/account) with `capability.type` such as `devices.capabilities.on_off`, `range` (brightness), `color_setting` (colorRgb int, colorTemperatureK 2000-9000), `dynamic_scene`, `segment_color_setting`. Daily cap widely reported as 10,000 requests (HA forum 429 text https://community.home-assistant.io/t/govee-integration/228516?page=58 ; Control4 driver doc https://drivercentral.io/images/CinSiteIcons/Govee/govee_gateway_documentation.pdf).
- BLE: no official protocol; reverse-engineered per model (H6001, H617A, H6199, H6054 ...) - usable from iOS via CoreBluetooth but brittle (https://github.com/chvolkmann/govee_btled , https://pypi.org/project/govee-h6199-ble).
- Matter: 2026 launches (E26 Edison G25, 1600 lm A19, ceiling/floor lights) are Matter-over-Wi-Fi - https://homekitnews.com/2026/05/15/govee-adds-full-colour-g25-matter-filament-bulb-to-lineup/ .
- HA `govee_light_local`: Local Push - https://www.home-assistant.io/integrations/govee_light_local/ .

### Nanoleaf
- Open API: TCP 16021; pairing via power-button hold then `POST /api/v1/new` (30 s window); reads at `GET /api/v1/{token}/`, writes `PUT /api/v1/{token}/state` (openHAB https://www.openhab.org/addons/bindings/nanoleaf ; Qodex mirror of docs https://developers.qodex.ai/program-smart-lights/nanoleaf-2/authorization-57/add-a-user-7). Use IPv4 - fw >=8.5.2 IPv6 discovery breaks requests (openHAB note).
- Official developer docs used to live at forum.nanoleaf.me/docs/openapi; that URL now 301s to a Zendesk "Developer Forum" (https://support.nanoleaf.me/hc/en-us/community/topics/42454879266836-Developer-Forum) that returned 403 to me - the docs' current home is **[uncertain]**.
- Essentials (Thread/BLE, incl. Matter Essentials) expose **no Open API**; HA: "Controlling Nanoleaf Essentials lights is possible over Thread and Bluetooth through the HomeKit Controller integration" - https://www.home-assistant.io/integrations/nanoleaf/ . openHAB: Open API "only supports devices that are connected through Wi-Fi". Older Essentials never got Matter (https://matter-smarthome.de/en/products/nanoleaf-no-matter-updates-for-current-essentials-products/).
- Library: MylesMor/nanoleafapi (73 stars, 2024-02). HA `nanoleaf`: Local Push.

### Yeelight
- TCP 55443, JSON-RPC, no auth; "LAN Control" (was "Developer Mode") must be on; "LAN Control may only be available with the latest firmware" and no official way to change it - https://www.home-assistant.io/integrations/yeelight/ (Local Push). Some units (e.g. MJDP02YL) ship without LAN control (https://forum.yeelight.com/t/topic/22913). TapHome notes the protocol has no authentication or encryption (https://taphome.com/en/compatibility/yeelight/).
- Matter: Pro line via S20 gateway (https://en.yeelight.com/news-events/yeelight-pro-supports-matter/); consumer "Yeelight Smart Bulb" CSA-certified Matter-over-Wi-Fi 2025-09 (https://csa-iot.org/csa_product/yeelight-smart-bulb/); Yeelight hubs becoming Matter controllers (https://www.matteralpha.com/news/yeelight-opens-up-its-platform-for-third-party-matter-lights-and-sensors).
- Library python-yeelight (268 stars, last push 2021 - protocol is stable, so age is OK).

### Tuya white-label (Feit, Globe, Merkury/Geeni, Smart Life, Teckin, Gosund, Treatlife, Sylvania Wi-Fi, Cree)
- Local key is the blocker: needs a Tuya IoT Platform (iot.tuya.com) developer project linked to the Smart Life account; trial "cloud development plan" expires and must be renewed (https://community.home-assistant.io/t/other-options-when-tuya-iot-expired/542767?page=2 ; 2026 guide https://privatehomelab.com/tuya-local-key-extraction-guide-2026/). Re-pairing rotates the key (https://community.home-assistant.io/t/tuya-local/237963?page=9).
- Tuya-local's QR-login path avoids the developer account but still talks to Tuya cloud (same 2026 guide).
- HA core `tuya` is Cloud Push and uses QR login with the Smart Life user code - https://www.home-assistant.io/integrations/tuya/ .
- Sylvania Smart+ Wi-Fi: HA users needed frida-trace on a rooted Android to get keys; linking to LocalTuya can break Alexa/Google control - https://community.home-assistant.io/t/sylvania-smart-wifi/223985 .
- Treatlife is explicitly listed among Tuya brands (https://joinhomeshift.com/blog/tuya-home-assistant/).
- For an iOS app: asking a consumer to create a Tuya developer project is unrealistic; realistic routes are (a) Tuya Cloud OpenAPI with your own app credentials and a "Smart Life" account link (Tuya "Cloud development" paid tiers), or (b) Matter for Matter-certified Tuya SKUs.

### GE Cync
- Local control exists only by impersonating the cloud: router DNS must point the Cync cloud hostname at a local TLS server (port 23779); at least one mains-powered Wi-Fi Cync device needed to bridge BLE-only bulbs; "strongly advise against firmware upgrades" - https://github.com/Proxy-alt/cync-lan , https://community.home-assistant.io/t/integration-for-local-cync-c-by-ge-control-no-mqtt-no-docker/1018872 . Not feasible inside an iPhone app. The `cync-lan` PyPI package (0.4.0) is a protocol library with packet codec, cloud auth and BLE provisioning - https://pypi.org/project/cync-lan/0.4.0/ .
- Matter: GE said at CES 2023 that existing products would not get Matter; new Matter SKUs (Cync Full Color A19, Reveal) list Matter 1.3 - https://www.techradar.com/news/ge-lighting-grows-its-dynamic-effects-lights-by-embracing-the-matter-standard , https://www.matteralpha.com/ge-lighting-a-savant-company/cync-reveal-full-color-light-p2595 .
- Recommendation: support Cync only via Matter (new SKUs) or via HA + cync_lights (cloud).

### Sengled
- Zigbee bulbs are end devices (don't route) and work with any Zigbee coordinator (Z2M pages e.g. https://www.zigbee2mqtt.io/devices/E11-G13.html). From an iPhone there is no Zigbee radio - go via HA/Hubitat/SmartThings or a Matter-bridging hub.
- Matter-over-Wi-Fi bulbs since 2023; "no mention of an update for their Zigbee hubs" - https://homekitnews.com/2023/08/04/sengled-has-released-its-first-matter-enabled-smart-multicolour-bulb/ .
- Wi-Fi (non-Matter) bulbs: cloud MQTT only, unofficial `ha-sengledapi`.

### Wyze
- Cloud only; wyze-sdk "entirely reverse-engineered, may break at any time" - https://github.com/shauntarves/wyze-sdk , https://wyze-sdk.readthedocs.io/ . Wyze requires an API key + key-id from the Wyze developer portal in addition to email/password for login **[knowledge]**.
- No Matter and no HomeKit; Wyze confirmed no firmware path to Matter - https://blog.athbridge.com/wyze-homekit/ , https://www.addtohomekit.com/blog/wyze-homekit/ .

## 3. Cross-cutting: Matter as the unifying layer

**Who ships Matter lights in 2026 (all Matter-over-Wi-Fi unless noted):** LIFX (Wi-Fi now, Thread beta), Tapo (L535E/B), Govee (2025-26 bulbs/lamps/strips), Nanoleaf Essentials (Thread), Sengled (Wi-Fi bulbs), GE Cync (new SKUs only), Shelly Gen3/Gen4 bulbs, Yeelight (new bulb, Cube, Pro via gateway), Eve (Thread, not the Wi-Fi Light Strip), IKEA via Dirigera bridge, Aqara via hub bridge, SwitchBot via Hub 2/3 bridge (beta), some Tuya-based SKUs (Feit/Globe - verify per SKU). **No Matter:** Wyze, Lutron Caseta, Elgato, Twinkly, Magic Home, Amazon Basics, Eufy Lumos, Meross bulbs (plugs only), Nanoleaf Wi-Fi panels (as of last public statement).

**Can an iOS app commission/control Matter directly?**
- Apple's developer page (https://developer.apple.com/apple-home/matter/): iOS 16.1+ includes Matter; "third-party Matter ecosystem apps can also easily request users' permission to access these accessories using the MatterSupport Framework"; "Apps that don't implement their own Matter ecosystem can use the HomeKit API to control Matter accessories in addition to HAP accessories"; "Xcode includes the certified Matter SDK in its entirety" (`Matter.framework`, `MTRDeviceController`).
- MatterSupport flow: your app ships a `MatterAddDeviceExtensionRequestHandler` extension; iOS scans the QR, provisions Wi-Fi/Thread credentials ("Your app does not have to prompt the user for network credentials"), and "iOS will return a pairing code to your app, and your app can proceed to set up its administrator fabric on the accessory via IP". So the app becomes its own Matter controller (own fabric, own key storage, CASE sessions, mDNS `_matter._tcp` discovery, `NSBonjourServices` entries `_matter._tcp`, `_matterc._udp`, `_matterd._udp`). Apple DTS: MatterSupport "primarily exists to support other general ecosystem vendors that have their own ecosystem platform" (https://developer.apple.com/forums/thread/766028).
- Hub: Apple's Matter page does not require a HomeKit home or home hub for MatterSupport. The Home app on iOS 18 with iPhone 15 Pro+ can even commission Thread devices without a hub (https://support.apple.com/en-us/HT213441). **But for third-party apps, Thread devices fail with "Thread Border Router Required"**: DTS (Nov 2024, FB15614070): "the system does not currently support this. The devices thread radio does not expose itself as a border router, which means it's not accessible to your app or MatterSupport extension" (https://developer.apple.com/forums/thread/766729). No evidence this changed since **[uncertain]**.
- Matter-over-Wi-Fi vs Thread: Wi-Fi Matter devices are reachable directly over IPv6 on the LAN (mDNS), so an app-side controller works with no hub. Thread devices need a border router (HomePod mini, Apple TV 4K Wi-Fi+Ethernet, or a third-party BR) on the LAN; HA's Matter page says the same ("To use Thread devices you will need a Thread network with at least one Thread border router") - https://www.home-assistant.io/integrations/matter/ .
- Remote (off-LAN) control of your own fabric requires your own relay infrastructure; Apple Home gets that from the home hub for free.
- Multi-admin: a device can sit in Apple Home *and* your app's fabric (spec minimum 5 fabrics per HA docs), but each extra fabric is another commissioning window the user must open from the Home app.
- Google's iOS Home APIs show the "ecosystem vendor" pattern concretely: an extension subclassing `MatterAddDeviceExtensionRequestHandler`, with commissioning executed through a hub - https://developers.home.google.com/apis/ios/commissioning .

## 4. Cross-cutting: HomeKit framework as the back door

- Confirmed by Apple: "Once added, Apple Home transparently supports Matter accessories in the Home app, Siri, Control Center, and in third-party HomeKit apps" and "A HomeKit entitlement is sufficient to access all accessories the user added to Apple Home, without having to explicitly re-pair accessories" (https://developer.apple.com/apple-home/matter/). So any brand the user has in Apple Home - via native HAP (Lutron, Eve, Meross HK, Twinkly Gen II, Sylvania BLE, Nanoleaf, Aqara hub, IKEA Dirigera) or via Matter (everything in section 3) - is reachable through `HMHomeManager` / `HMAccessory` / `HMService` / `HMCharacteristic`.
- Requirements: HomeKit capability (`com.apple.developer.homekit` entitlement) + `NSHomeKitUsageDescription`; user grants permission at first launch (https://www.cmarix.com/homekit-integration-with-ios-mobile-app). Apple's own HomeKit doc pages did not render through my fetcher, so exact limitation text was not quoted **[knowledge for: not available in app extensions; Mac Catalyst needs entitlement]**.
- Limitations: (1) user must set up an Apple Home and add devices there first; (2) remote access, sharing and automations require a home hub (HomePod/Apple TV) - https://support.apple.com/en-in/HT207057 ; (3) you only get the HAP/Matter characteristic surface (on/off, brightness, hue/sat, colour temperature) - vendor effects/scenes (Twinkly effects, Nanoleaf scenes, Govee DreamView) are not exposed; (4) Thread-only devices need a border router unless the user is on iPhone 15 Pro+/iOS 18 via the Home app; (5) to *add* HAP accessories from your app use `HMAccessorySetupManager` (iOS 15.4+) **[knowledge]**; adding Matter accessories *into Apple Home* from your app is not what MatterSupport does - it commissions onto *your* fabric (DTS, https://developer.apple.com/forums/thread/766028).
- Note on HA's HomeKit Device integration: "HomeKit devices can only be paired to a single controller at once" (https://www.home-assistant.io/integrations/homekit_controller/) - a HAP (non-Matter) device is in Apple Home *or* in HA, never both.

## 5. Cross-cutting: Home Assistant as a backend

- REST: `GET /api/`, `GET /api/states`, `GET /api/states/<entity_id>`, `POST /api/services/light/turn_on` with `{"entity_id": ..., "brightness": ...}`; "Every request needs an access token in the `Authorization` header" (Bearer; long-lived token from profile > Security); default port 8123 - https://contributors.home-assistant.io/core/internals/rest-api/ .
- WebSocket: `/api/websocket`; server sends `auth_required` -> client `auth` with `access_token` -> `auth_ok`; then `subscribe_events` (`state_changed`), `call_service`, `get_states`; every command carries an incrementing `id` - https://contributors.home-assistant.io/core/internals/websocket-api/ .
- Swift client: `home-assistant/HAKit` (Swift, 55 stars, pushed 2026-10-16; SPM/CocoaPods; v0.4.4 Dec 2024) is the library the official companion app uses - https://swiftpackageregistry.com/home-assistant/HAKit .
- Remote access: Nabu Casa cloud or the user's own reverse proxy/VPN; your app just needs base URL + token.
- Integration breadth for the brands here (IoT class from each HA docs page): LIFX Local Polling; TP-Link Kasa/Tapo Local Polling (needs cloud creds for new devices); Govee LAN Local Push (cloud Govee only via HACS); Nanoleaf panels Local Push (Essentials via HomeKit Device); Yeelight Local Push; Tuya core Cloud Push (tuya-local/localtuya HACS for local); SwitchBot BLE Local Push + switchbot_cloud Cloud Polling; Shelly Local Push; Lutron Caseta Local Push; Twinkly Local Polling; Elgato Local Polling; flux_led/Magic Home Local Push; Tradfri gateway Local Polling; Dirigera via HomeKit Device/Matter (or HACS dirigera_platform); Matter Local Push (needs Matter Server add-on, IPv6; commissioning only from the HA Companion app, iOS >=16.4; Bluetooth on the phone only for pairing); HomeKit Device Local Push; WiZ Local Push; Wyze HACS ha-wyzeapi (cloud, 1,004 stars); Cync HACS cync_lights (cloud) or cync-lan (local, DNS hijack); Sengled Zigbee via ZHA/Z2M, Wi-Fi via HACS cloud; Meross HACS meross_lan (local); Aqara via Matter/HomeKit Device/ZHA; Eufy legacy integration currently broken (2026.10).
- Net: HA covers every brand on the list in some form and normalises them to one `light` entity model, at the cost of requiring the user to run HA.

## 6. Suggested tiering for the app

1. **Tier 0 - HomeKit framework** (zero protocol work; covers Lutron, Eve, Twinkly, Sylvania BLE, Meross HK, Nanoleaf Essentials, IKEA, Aqara and every Matter device the user has put in Apple Home).
2. **Tier 1 - documented local protocols**: LIFX (UDP), Elgato (HTTP), Shelly (RPC), Nanoleaf panels (REST), Govee LAN (UDP), Yeelight (TCP), Magic Home (TCP), Twinkly (HTTP), Dirigera (REST). All plain sockets/HTTP - straightforward in Swift with Network.framework/URLSession; need `NSLocalNetworkUsageDescription` + Bonjour service list.
3. **Tier 2 - official cloud APIs with user-supplied keys**: LIFX HTTP, Govee Developer API, SwitchBot v1.1, (Tuya Cloud OpenAPI if you register as a Tuya developer).
4. **Tier 3 - reverse-engineered with credentials**: Tapo/Kasa KLAP (cloud creds + toggle), Meross local (cloud key), Wyze (cloud only), Tuya local (local keys).
5. **Tier 4 - your own Matter controller via MatterSupport + Matter.framework** (Wi-Fi Matter devices without needing Apple Home; Thread still needs a border router).
6. **Tier 5 - Home Assistant bridge** for everything else (Zigbee Sengled/Aqara/Sylvania, Cync local, Eufy).
Not worth doing: Amazon Basics, Cync cloud-impersonation inside the app, Tradfri CoAP/DTLS.
